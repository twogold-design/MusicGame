# 喵喵打碟俱乐部 / MEOW BEAT — 首版玩法方案

本文为策划建议；实际发布功能和数值以游戏及 README 为准。技术方案已按用户最终要求调整为 Godot 4.7.2 的 2D 网页游戏，音乐使用原创 WAV、谱面使用 JSON，Godot 负责显示与输入判定。

## 一句话

用四个按键和猫咪 DJ 一起打碟，命中节奏点亮舞池，积攒能量自动进入派对时刻，在一分钟左右的原创电子音乐中挑战更高评价。

## 玩家乐趣

- 立即听懂：第一首节奏稳定，短旋律在乐句间重复，音符贴合清晰的鼓点与旋律。
- 立即看懂：四条轨道固定对应 D、F、J、K；音符中心碰到横向判定线时按键。
- 有成长：准确命中 → 连击上涨 → 舞台更热闹 → 派对时刻 → 结算评级 → 再挑战。
- 能放松：不设血量失败；错过几个音符也可以完整听完歌曲。失误失去连击，不失去继续玩的资格。
- 能追分：不同歌曲、难度分别记录最高分和最高准确率；全连与全 Perfect 有清晰奖励称号。

## 内容范围

| 曲目 | BPM | 氛围 | normal 谱面定位 |
|---|---:|---|---|
| 落日汽水 | 100 | 橘粉落日、轻快合成器 | 入门曲，四分音符为主，少量八分音符，介绍长按 |
| 霓虹夜行 | 120 | 青粉霓虹、夜间俱乐部 | 交替键与双押，较短的八分音符乐句 |
| 星际派对 | 140 | 蓝紫星空、明亮电子乐 | 更紧凑的交替与长按组合，仍保持可读性 |

每首预计约 55–70 秒。全部曲目直接可选，不用解锁。easy 模式降低音符密度、去除复杂双押，保持同一首音乐和原有时长；不只是降速。

## 操作与开局

- 键盘：D / F / J / K；Esc 暂停。
- 触屏：底部四块宽大的按键，支持两个以上手指同时按下。
- 普通音符：中心到达判定线时点一下。
- 长按音符：头部到线时按住，直到尾部通过判定线再松开。
- 选曲后 3 秒倒数。开局前展示一句提示：“音符到线时按 D F J K；长条按住到尾。”
- 第一首前 8 拍以单轨、单键音符开始，后续逐渐引入交替和长按；不要一开始就双押。
- 选择页面显示歌曲难度、时长、BPM 和自己的最好成绩，避免把参数藏进设置页。

## 判定建议

所有判定使用音频时钟，音符绘制仅作为时钟的可视化。以下窗口以输入时刻减目标时刻的绝对值计算。

| 判定 | normal 窗口 | 分数系数 | 准确率权重 |
|---|---:|---:|---:|
| PERFECT | ≤65ms | 1.00 | 1.00 |
| GREAT | ≤110ms | 0.70 | 0.75 |
| GOOD | ≤160ms | 0.40 | 0.40 |
| MISS | 超过末端窗口 | 0 | 0 |

easy 可放宽到 85 / 140 / 200ms。空敲不扣分、不改变连击，也不能得分；同一轨道同一次按下只消耗最近的一个未判定音符。忽略键盘自动重复，防止按住一个键持续刷普通音符。按下事件必须从抬起状态变化而来。

长按头部沿用普通音符判定。尾部允许提前 100ms 松开；更早松开视为断尾，连击重置。建议每条长按仅计一个头判定和一个尾判定，不按每帧累计分数，保证不同帧率成绩一致。可选简单实现：头部标准分 1000，成功保持到尾部另得 400；断尾不撤回头部已获得的分数。结算要把长按尾判定也纳入准确率分母，防止只点头部获得虚假全准。

长按不能在同轨道覆盖新的音符。自动判漏时保证每个音符只结算一次。暂停、切后台时冻结音频与判定，恢复时使用短倒数或给清晰提示，避免浏览器后台造成突然全漏。

## 计分、连击和派对时刻

普通音符基础 1000 分，按判定系数计分。GOOD 及以上增加一次连击；MISS、断尾重置连击。建议连击主要作为表现和结算挑战，不叠加复杂倍率，首次游玩更易理解。

派对能量建议：PERFECT +10，GREAT +7，GOOD +4，MISS -15，范围 0–100。满能量自动进入派对时刻，持续 8 拍，期间所有有效得分 ×1.5。期间不继续储能，结束清空后重新积攒。派对剩余时间按歌曲拍数计算，在各 BPM 下都保持一个乐句的完整性。触发时显示“派对时刻 ×1.5”，猫咪加大摆动、灯光变亮，鼓组或高频层略增强，但不能让听觉变得刺耳。

派对不能因空敲触发，不能因暂停/恢复重复发奖励。连击里程碑建议 10、25、50、100，最多显示一个短提示，不覆盖来谱。

若首版时间紧，保留“准确率 + 最大连击 + 自动派对”，优先舍弃复杂倍率和解锁系统。

## 结算

准确率独立于派对奖励：各判定准确率权重总和 ÷ 全部判定点数量。它不应等于最终分数除以理论基础分，否则派对会使准确率超过 100%。

| 评级 | 准确率 |
|---|---:|
| S | ≥95% |
| A | ≥85% |
| B | ≥70% |
| C | ≥50% |
| D | <50% |

结算显示：大号等级、最终得分、准确率、最大连击、PERFECT / GREAT / GOOD / MISS 计数。没有 MISS 或断尾授予“全连”；全部 PERFECT 且全部长按完成授予“全场完美”。无输入一曲不能给全连。

主按钮“再来一首”，次按钮“再挑战一次”。个人记录分歌曲和难度保存；新纪录突出展示。存储不可用时继续允许游玩，不因浏览器隐私模式崩溃。

## 美术和交互重点

藏青底色、酸橙黄主按钮，青色与珊瑚粉为灯光强调色。音符需要比背景更亮，普通音符和长按尾部明确区分。每条轨道既有颜色，也有固定位置和键位文字，不只靠颜色识别。

猫咪和城市是气氛层，不抢音符对比度。首页可以华丽，游戏区背景要安静。判定字样在中央上方出现，不能遮挡接近判定线的音符。失误反馈短而轻，避免大面积闪屏；提供音量控制。

可明确沿用的交付方式：

1. 提交 ZIP，完整解压后根目录存在 `index.html`。
2. 上传全部运行资源到静态比赛平台，入口指定 `index.html`。
3. 无账号、无后端也能游玩完整单机内容。
4. 素材运行时无需外部网络请求；可在 Chrome / Edge 本地文件方式离线打开。
5. 本项目采用 Godot 2D Web 导出，建议使用单线程、兼容性渲染器，浏览器需支持该导出的 WebGL 2 运行条件，但不要求跨源隔离响应头。这是引擎要求，不是已确认的比赛要求。若需本地双击 HTML，应像参考项目一样解决文件协议资源加载，不能只假设 Godot 默认导出就可双击运行。
6. 严格按 200,000,000 字节上限同时校验压缩前和压缩后大小。参考构建脚本对解压体积硬检，ZIP 大小仅写入清单，本项目应补齐双重硬检。
7. 用户额外要求：工程、缓存、临时文件、构建和测试产物全部留在 `M:\NewGames\MusicGame`，不写入 C 盘。
